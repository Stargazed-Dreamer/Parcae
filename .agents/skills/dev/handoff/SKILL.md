# Handoff（会话交接）

交接稿是**给一个没有这段记忆的 agent 的启动盘**，不是会话记录。

唯一的验收标准：**读者只有这份稿 + 仓库，不需要问任何「上面说过」**。任何一句依赖"刚才那段对话"才能理解的表述，都是缺陷。

它和日志的分工：`.agents/memory/YYYY-MM-DD.md` 记**发生过什么**（全量、流水、给人看）；交接稿只留**从这儿接着做需要什么**（极简、给 agent 看）。所以交接稿的内容几乎全部来自日志和现场命令，只是**重新排序 + 删减**，不重新创作。

## 改造说明（原版 → 本版）

原版（mattpocock/skills `productivity/handoff`，16 行 / 940 字节）只有写入侧，要求存 OS 临时目录。本版：

- **落盘**：本项目 `temp/handoff/HANDOFF_<YYYY-MM-DD>_<主题>.md` —— `temp/*` 已被 `.gitignore:18` 忽略，天然不入库；比 `%TEMP%` 好在固定路径、任何 harness 都找得到、不会被系统清理器随机删（本目录已登记进 `temp_cleanup.md` 保护清单）
- **不注册 `wip_tasks`** —— 稿子是"这次卡在哪"的一次性视图，删掉文件后 DB 会留悬挂记录；"这活还没完"由 `wip_tracker` 的 WIP 记录负责，两者分工不重叠
- **加接手侧**（原版完全没有）—— 否则这个 skill 只是"写文档"，闭环不了
- **加生命周期** —— 原版靠 OS 清理，本版必须自己说清什么时候删

## 一、边界：四个邻居不重叠

| 邻居 | 它管什么 | 分界 |
|---|---|---|
| `wip_tracker` | 未完成任务台账（真源 `wip_tasks` 表） | WIP 说「这活没完」，可跨会话查询；交接稿说「这次具体卡在哪儿」，**被新稿取代或任务完成时删** |
| `task_closure` | 任务闭环 + 收尾报告 | 收尾可以没有下一会话；交接的前提就是**有**下一会话 |
| `cross-machine-delivery-bundle` | 跨机交**文件**（压缩包 + 完整性清单 + 交付说明 + 落地脚本 四件套） | 本 skill 交**状态**。⚠ "跨机交接"一词已被它占用，本 skill 只说"换会话 / 交交接稿" |
| `neat-freak` | 改项目文档、做长期同步 | 它的 description 里有「给队友/其他 agent **干净交接**」，指的是**把项目文档整理到新人能直接上手**，不是会话状态传递。本 skill **只产出一份一次性稿**，不改项目文档（`AGENTS.md` / `TOPIC_*.md` / ADR）；唯一例外是经用户确认删除入库旧稿 |

判断入口：**下一句话是"我换个对话接着做"→ 本 skill；"这活先记下来，以后再说"→ `wip_tracker`；"整理一下这些文档"→ `neat-freak`。**

## 二、落盘与生命周期

```
temp/handoff/HANDOFF_<YYYY-MM-DD>_<主题>.md
```

- 目录不存在就建：`mkdir -p temp/handoff`
- 一个任务**只保留一份当前稿**。写新稿时显式删掉同主题旧稿——文件名带日期，**新稿不会覆盖旧稿**，必须手动删
- 任务完成后**整份删**。它没有归档价值——发生了什么在当日日志里，未来的任务不需要读旧交接稿
- 接手会话把头部状态改成 `已接手`，**但不立刻删**：接手会话本身也可能再断一次，那时它是唯一锚点。等它写出新稿（那时删旧的）或任务完成（那时删），旧稿自然消失
- 并行任务可以有多份，靠文件名主题区分；不要建子目录
- **死稿兜底**（两种，都只列清单、不自动删）：① 仍是 `待接手` 且 mtime > 7 天 ⇒ 没人来接手；② 已改成 `已接手` 但 mtime > 7 天、期间既没产出新稿也没走到任务完成 ⇒ 接手会话也中断了。两种都视为"不会再有用"，下次清理 `temp/` 时**列进待定清单交给用户**（`temp_cleanup.md` 的规矩：保护类不删，争议交用户）

⛔ `temp/` 下的稿删除一律走 `uv run python tools/disk/recycle.py "<绝对路径>"`（送回收站），**不用 `rm`**——本机 `rm` 是 `/usr/bin/rm` 物理删除，`AGENTS.md:499` 明令禁止。已入库的 `.agents/memory/` 旧稿**不适用本条**：它是 git 操作，先报告用户、确认后 `git rm`（见接手流程第 2 步）。

头部三字段（必填）：

```markdown
> **状态**：待接手 | 已接手　**生成**：2026-10-25 02:30 GMT+8　**下一会话重点**：<一句话>
```

  —— 那里只留 2026-10-26 及更早的历史稿（读一次即可）。

## 三、交接稿骨架（7 段，顺序即优先级）

预览器常常只显示开头，所以卡点必须在第 0 段。

```markdown
# 交接：<一句话主题>（YYYY-MM-DD HH:MM）

> **状态**：待接手　**生成**：<时间>　**下一会话重点**：<一句话>

## 0. 卡点（一句话）
现在到底卡在哪。写不出这一句，说明还没到该交接的时候。

## 1. 目标与验收
这活要达成什么；**怎么算做完**（可执行的判据，不是"跑通就行"）。

## 2. 已落地且已验证
| 改动 | 位置 | 怎么验证的 |
|---|---|---|
| ... | `path:line` / commit | 跑了什么命令、结果是什么 |

只写**已验证**的。没验证的移到第 3 段。

## 3. 现场状态
分支名、脏文件、运行中的进程/端口、失败的测试批次（带批次名和原因码）、未提交的改动。

## 4. 已决策与理由
已经拍过板的事 + 为什么这样定。**目的是防止下一会话翻案重做。**

## 5. 待裁决（谁定）
还没定的事，标清是「等用户拍板」还是「等技术验证」。

## 6. 接手顺序 + 建议调用的 skill
1. <第 1 步必须现在就能执行，不能是"先了解一下">
2. ...
建议：`dev/xxx`（为什么）、`xxx`（为什么）
```

两条硬规则（原版 ③④，保留）：

- **不复制其他产物的内容**。spec / ADR / issue / commit / diff 只给 `路径:行号`、commit hash 或 URL，让接手者自己去读原文。
- **脱敏**。API key、token、密码、个人身份信息一律不写。

本版新增一条：**第 2 段每条"已完成"必须自带验证方式**。没有验证方式的"已完成"等价于"我以为做完了"，是交接稿最常见的毒点。

## 四、写入流程

1. **够格判定**（不满足就直说不用写，别产垃圾稿）
   - 实质交流 < 3 轮，或状态已完全体现在 commit/PR 里 ⇒ 不写
   - 活已干完、没有下一会话 ⇒ 不写
2. **取证据，不靠回忆**：跑 `git status` / `git log --oneline -5` / 读失败日志 / 看端口，把数字抄进第 3 段
3. **按骨架填**，位置一律带路径，尽量带行号；用户说了"下一会话要做什么"，就按它调整第 1 / 6 段的详略（原版 ⑤ 的裁剪要求）
4. **零上下文自检**：从头读一遍，搜「上面」「刚才」「之前说的」「那个」——每出现一次就改成具体指代（文件、命令、结论原文）

## 五、接手流程

1. `mkdir -p temp/handoff && ls -t temp/handoff/*.md 2>/dev/null | head -5`，选状态为 `待接手` 的那份。
   **目录为空或不存在就直说"没有交接稿"**，不要静默当成无事可做。
2. 旧路径也算：`temp/handoff_*/`（历史日期目录）、`.agents/memory/HANDOFF_*.md`（含 2026-10-25 当天及更早按旧路径写的稿，先用 `git status` 查有没有未跟踪的）。历史稿**读一次**即可，接手后按新规矩写到 `temp/handoff/`。
   ⚠ `.agents/memory/` 下的是**已入库**文件：删除要先报告用户、确认后用 `git rm`；只有 `temp/` 下自造的稿才能自行送回收站。**不留双轨**，但也不擅自删入库文件。
3. **先读稿，再读它引用的文件**。不要跳过稿子直接猜，也不要只读稿子不看代码
4. **只信证据，不信叙述**：稿子里每条"已完成"都去核对一次（`git log`、文件是否存在、测试是否真绿）。稿子与仓库冲突时 **以仓库为准**
5. 接手后把头改成 `已接手`；发现稿子有错，就地修正——下一个接手的人会感谢你

## 六、反模式

| ❌ 反例 | 为什么错 |
|---|---|
| 把整个对话摘要一遍 | 那不是交接稿，是劣质日志。下一会话要的是"从哪继续"，不是"聊过什么" |
| "按照上面的方案继续" | 上面不存在。新会话没有"上面" |
| "测试基本都过了" | 不可验证。要写"32 批 / 5122 passed, 1 failed（批次 `tests/lib_core`）" |
| 交接稿留在 `temp/` 三个月 | 它已经过期，读它会走错路。要么被新稿取代，要么删；改过状态的死稿则列给用户裁决（见生命周期） |
| 把交接稿当项目文档维护 | 一次性稿没有维护价值；要长期留的写 `TOPIC_*.md` 或 ADR |
