# 实战案例：2026-10-23 `<data_drive>:/<media_staging>\new` 整理

一次完整的「混装目录 → 142 个平铺视频」的实录。数字与坑都可复算，用来校准下一轮的预期。

## 1. 起点

- 目标目录：`<data_drive>:/<media_staging>\new`，视频、加密 zip、子目录、txt/exe 杂物混在一起；
- 命名要求：`M-D 角色 原画/差分`，全部平铺；
- 用户的硬约束：**「上一个执着于脚本一键完成的误删了我的所有文件」** ⇒ 分批 + 预检 + 回读；
- 用户四个决策：zip 解压平铺 / mp4 原地改名 + zip 与杂物进回收站 / 角色名先保留原写法 / 模糊项按默认。

## 4. 踩过的坑（按发生顺序）

### 4.1 盘点漏文件

第一版 mapping 脚本漏了 `10-11\洛茜原画.mp4`（在子目录里）。
**修法**：加「目录内每个文件在映射表里恰好出现一次」的覆盖断言。这类漏项不报错。

### 4.2 扫到巨型无关 zip

`Goo-Engine` 的 zip 内部 **5995 个条目**。一次「看看 zip 里有什么」的扫描直接 dump 了
**925 KB** 文本，把上下文打满，只能杀进程。
**修法**：按文件名排除无关包；给 entry 数设上限；输出必须带 `matched/N`。

### 4.3 staging 路径造出子目录

源名和 zip 内 entry 名都带 `\` `/`，直接拼 `.part` 路径会在 staging 下生成意料之外的目录树。
**修法**：

```python
safe = (source + "__" + zip_inner).replace("\\", "_").replace("/", "_")
```

### 4.4 Python 解密慢到像卡死

Z1 批跑 Python 解压，超过预期后只能 `TaskStop` 停掉（已完成 5 个）。
因为脚本设计成**幂等**（目标存在且大小/头正确就跳过），换 7-Zip 后重跑无缝续上。
教训：**批处理脚本必须幂等**，否则中断 = 重来。

### 4.5 7z 脚本参数校验写错

`sys.argv[1]` 是 `"Z1"`，却直接和 `GROUP_RANGES` 的整数键 `1..5` 比，永远不匹配。
**修法**：`sys.argv[1].startswith("Z") and sys.argv[1][1:] in GROUP_RANGES`，并打印实际解析值。

### 4.6 回收预检全部误判

`allowed_leftover()` 拿**绝对路径**去比较**相对路径**的 `zip_map` 键，导致永远认为「还有残留」。
**修法**：`os.path.relpath(path, ROOT)` 之后再比。

### 4.7 `mvhd` 解析全返回 None

递归找 `mvhd` 时忘了把内层返回值 `return` 上来，所有文件都判为「解析失败」，
一度以为这批 mp4 全是坏文件。修好后样本时长 9.7–17.2 s，全部正常。

### 4.8 同名冲突

同一天同一角色两份 → `差分1` / `差分2`，不用 `(1)` / `_v2` / `副本`。

## 5. 名字取证的实例

| 情况 | 原始线索 | 结论 |
|---|---|---|
| zip 名与内容不符 | `祀8-21.zip` 内是 `小葱8-21.exe` | 角色 小葱、日期 8-21 |
| zip 内名给出角色全名 | `9-7蕾米埃尔.zip` 内 `9-7蕾米差分.exe` | 角色 蕾米埃尔、版本 差分 |
| mtime 全是同一天 | 142 个文件 mtime 均 2026-10-13 | 弃用，改读 `mvhd` |
| `mvhd` 补日期 | 小葱 8-21、知更鸟 8-26、死执 8-13、水鸟摇一摇 8-26 | 补入映射表 |
| 无角色线索 | 一个 TG 视频，只能定位到 8-17 | 保留日期，角色留待用户确认 |
| 跨 IP 同名 | `提丰`（明日方舟）/ `提弗洛斯`（终末地再旅者） | **不同角色，不合并** |

## 6. 可复用的执行顺序

```
只读盘点 → 映射表 + 三条覆盖检查 → 批次切分
  → 每批：预检 → 逐条执行 → 回读数字
  → 全部完成后：回收清单 → 探针 → 分组回收 → 剩余集合核对
  → 官方名核对（WebSearch）→ 单独成批改名
  → 交付四份 CSV → verify_media_folder.py 全量核对
```

## 7. 复算方式

- 最终条数与总字节：`verify_media_folder.py <目录> --csv <最终清单>`
- 回收是否完整：目录内剩余集合 == 最终清单集合（脚本已含此项）
- 官方名修正依据：`new_异体字修正_20261023.csv` 的 note 列
