# 限流换号 → 接手被打断的会话

## 0. 这个 skill 解决什么

WorkBuddy 账号会撞限流（`429 您的使用量已超出频率限制，将在 … 重置`），一场长任务断在半路。
换号之后新会话**上下文是空的**，于是：①原来的活没人知道干到哪了 ②重开会话等于从头再问一遍。

本 skill 把「换号」变成固定三步，用户只需要报数字：

| 步 | 谁做 | 动作 |
|---|---|---|
| ① | 用户 | 限流后直接换号，发固定提示词：**「读 `<project_root>\.agents\skills\daily\wb-takeover\SKILL.md` 并按流程走，当前账号 <手机号>」** |
| ② | 你 | `scan` 出候选 → **在对话里按序号汇总**（每场一句：断了什么、断在哪、重置换算）→ 等用户报数字 |
| ③ | 你 | 用户报的数字 → `export --pick` 逐场出包 → **逐条给派发提示词**，用户贴到新会话里去 |

⛔ **用户报手机号不是为了让你反查 uuid**（库里查不到，见 §5.1）。它只是告诉你「现在是哪个号」，
用来区分「当前号」与「刚被限流的那一个」。解析不出来不影响主流程，别为了它停下来问。

## 1. 第 0 步：先扫一眼现场（30 秒）

```bash
cd <project_root>
uv run python -m tools.wb_takeover accounts      # 两个号各有多少会话、最后活动
```

- 主要就这两个号（uuid 前 8 位）：`988245f8`、`cb7cc21a`。**以本命令实测为准**，别背。
- 手机号 ↔ uuid 的映射**库里没有**（`~/.workbuddy/*.json` 无 account/phone 字段）。首次需要时：
  `uv run python -m tools.wb_takeover accounts --set <手机号>=<uuid8>`，落 `data/wb_accounts.json`
  （`.gitignore` 的 `data/*`，不入库）。⛔ **这个文件、skill、日志正文都不要写明文手机号**。
- 已经有映射时会直接显示在 `accounts` 输出里，此时 `--account <手机号>` 就能用。

## 2. 第 1 步（scan）：把候选摊开

```bash
uv run python -m tools.wb_takeover scan --skip-current             # 主用法：近 24h（默认窗口）
uv run python -m tools.wb_takeover scan --hours 72 --skip-current  # 往前翻几天
uv run python -m tools.wb_takeover scan --all                      # 全库（1.4GB，约 12s）
uv run python -m tools.wb_takeover scan --account 138xxxxxxxx
uv run python -m tools.wb_takeover scan --include-archived         # 连你已归档的也列出来
```

⚠ **默认窗口就是 24h**（用户 2026-11-01 定的：「限 24h 以内就行了」）。换号后要接的活几乎都在最近
一天里；超过这个窗口的多半已经用别的方式收过尾，列出来只会稀释判断。**别自作主张放宽**，
用户要看更久的会自己说。

⚠ **已归档的会话一律不列，连 429 也不列**（用户 2026-11-01 裁决：「归档确实不是活干完了，
但是是我明确不再理会的，你不用自作多情再掏出来问我。大概率都是有人接手或者情况有变，
归档一定是我明确不再管的东西。」）。

所以 `sessions.status` 要拆成两件事看：

- 判**「怎么断的」** → 只看 jsonl 尾条，`status` 没用（见坑 2）。
- 判**「还归不归我管」** → 只看 `status`：`archived` = 用户已明确收摊，**不管它断在哪都别列**。

库里 326 场有 285 场是 archived，是常态不是异常。唯一出口是 `--include-archived`（用户主动要看历史时才用），
默认连提示都不必多说，头部一行 `另 N 场已归档未列` 足够。

**默认就是三段式**，一次扫全，不用先猜是哪一类（编号跨段连续）：

| 段 | 标记 | 是什么 | 给你看几行 |
|---|---|---|---|
| 一 | `●限流` / `●401` / `●5xx` / `●未完成(其他)` / `●用户发了但无回应` | 被系统打断，断在半路 | 5–7 行：重置/标题/目录/末用户/末agent/末工具 |
| 二 | `◇ 等回话` | **正常收尾，但末句把球踢给你**（「等你上传」「你说一声」「要不要我…？」） | 3 行：标题 / `球在你 →` 那句 / 末用户 |
| 三 | `· 已完成` / `· 用户中断` | agent 说完了，或你自己按停的 | 2 行，扫标题看你还有没有想追加的 |

⛔ **别只盯第一段**。用户 2026-11-01 原话：「不只是 429 直接断的…有时候我没来得及处理后续，
agent 反馈了，我想继续却发现已断，看起来正常结束，但是实际上我还有话要说。」
⇒ 第二段就是为这个存在的，**它常常比第一段更该看**：限流前后那批活，大多数是收在「等你回话」上。

第一段的读法（**下面这几行比 `●限流` 那几个字有用得多**）：

```
[1] 509918f7  另一号  ●限流  2026-11-01 04:03  2.1MB  9msg/192call  ctx 84k/300k
    重置  2026-11-02 01:03:04 UTC+8
    标题  探索 neoschool 网页抓取作业文档
    目录  <project_root>
    末用户 [2026-11-01 04:00] 补一下L02
    末agent 课号已确认（week2 = …）。先从平台回放页打开 L02，再开始收割。
    末工具  Bash: … /temp/neo_playrecord_l02.py
```

读法（**下面这几行比 `●限流` 那几个字有用得多**）：

| 字段 | 用来判断什么 |
|---|---|
| `末用户` | 用户最后要的是什么 —— 接手的目标在这 |
| `末agent` | agent 已经做到哪、自己认为下一步是什么（**最后一条正常回复**，已跳过错误横幅） |
| `末工具` | 断在哪一步动作上（编辑到一半？脚本刚跑起来？） |
| `重置` | 限流解除时间。**当前时间还没到重置点 ⇒ 那个号确实还得等**，不是「等会儿就能用」 |
| `ctx` | 接近 300k 的场次后半段靠压缩摘要接的，读历史时要留神（见 §5.4） |

### 2.1 挑哪几场给用户（默认口径）

- **第一段全列**：`●` 都是硬断，没有「该不该接」的余地。
- **第二段全列**：`◇ 等回话` 就是「你还有话要说」的那批。⚠ 它靠**末句措辞**认，会有假阳性
  （实测 14 条里 1 条是正文引用了别人的「是否要更严」）。挑的时候**扫一眼 `球在你` 那句**，
  明显不是问你的就剔掉。
- **第三段挑**：扫标题，只有你认得出「这活明明还有下一步」的才列；其余默认不列（接它等于重做）。
- 排序不用动：`scan` 已按最后活动倒序（段内）。用户要的是「按时间倒序」，别自己重排。

### 2.2 汇总给用户（这是第 1 步的交付物）

⛔ **不要把 scan 输出原样贴给用户**，他要的是能一眼挑的清单。按段汇总、每场 1–2 行：

```
**断了半路的（限流 / 报错）**
[1] 探索 neoschool 网页抓取作业文档（另一号，限流，重置 11-02 01:03）
    断在：L02 课号刚确认、收割脚本刚跑起来，还没出数据。
[2] 优化 chat digest 数据提取的 token 消耗（另一号，限流，重置 11-02 01:03）
    断在：首轮就被限流，一行都没开始分析。

**看着收尾了、其实在等你回话的**
[3] 清理 rubbish 文件夹并映射工作区（另一号）
    球在你：有个超配额被永久删的要不要追。
[4] 查看可并行作业（当前号）
    球在你：后端 8766 不响应，要不要另找时间重启。
```

- 序号**跨段连续、从 1 开始、与 `last_scan.json` 对齐** —— 用户只回数字。
- 「断在 / 球在你」这两句是**你自己读完写的**，不是脚本给的。
  ⛔ 别把脚本输出当结论复述（项目红线：结论靠现场判断，不让脚本代判）。
- 第二段每条**必须写清「要你做什么」**——用户就靠这一句决定接不接。
- 末尾提醒一句：`回复序号我来导包（可多选，如 1、3）`。
- 顺手标出**与自己相关的那场**：`--skip-current` 只挡「当前号正在运行」的，扫出来里可能还有本次
  对话自己（标题就是本次发起的活）——别把你自己列进待接手清单。

## 3. 第 2 步（export）：逐场出包

用户回了数字之后：

```bash
uv run python -m tools.wb_takeover export --pick 1,3 --note "断点一句话"
uv run python -m tools.wb_takeover export 509918f7 --note "…"     # 直接给 id 也行
```

- `--pick` 读 `temp/wb_takeover/last_scan.json`，把数字翻回会话（**所以别让用户记 uuid**）。
  ⚠ **编号只对最后一次 scan 有效**：中间又跑过 scan，就重新报一次序号给用户对齐，别硬套。
- `--note` 写 1-3 句断点说明，会进派发提示词。**没细读就写你确实知道的那点**，宁短勿编
  （用户明确说过：不必细读会话写 handoff，把源文件放进去让接手方自己读）。

产物落在 `temp/wb_takeover/<最后活动日期>/<会话8位>/`：

| 文件 | 是什么 | 接手方怎么看 |
|---|---|---|
| `HANDOFF.md` | 事实头：元数据 / 尾部 6 条原文 / 断点前 25 条工具调用流水 / 改动过的文件 | 先看，2 分钟 |
| `chat_full.md` | 全量对话（U/A 双方，注入块已剥净，`[n]`=全量条目序号） | 主要上下文 |
| `source.jsonl` | 原 jsonl 的**拷贝**（沙箱可能不许读家目录，所以复制而不是给原路径） | 要逐字核对工具参数/回显时 |
| `PROMPT.md` | 派发提示词 | 贴给新会话 |

- 包目录全是 ASCII 短路径（`2026-11-01/509918f7/`），避免中文路径在某些工具里失联。
- 重复 export 同一场会**整份覆盖**，别在那里手写批注。
- 出口时会打 `收尾= / 消息= / 工具= / 改动文件=` 和整份 `PROMPT.md`。

**回报给用户时**：每场两行 —— `包路径` + `这包多大/多少条`，不用复述 PROMPT（下一步才给）。

## 4. 第 3 步（派发）：给可粘贴的提示词

用户要自己把提示词贴到新会话，所以**在对话里逐条给完整文本**（不要只说「包好了，去读 PROMPT.md」）：

⛔⛔ **每一场都要从标题行到最后一个字完整贴一遍，一个字都不许省。禁止「同上文」「同上」「其余同上」
「只有这两行不同」这类写法**（用户 2026-11-01 明确要求）。他是一条一条复制去派的，省略一次他就得
自己回头拼一次；拼错了派出去的是错的提示词，而且他不会发现。
即使两场的 `PROMPT.md` 只差标题/路径/断点那几行，也**照抄全文**。

```
**第 1 场 · 探索 neoschool 网页抓取作业文档**
```
<PROMPT.md 的全部内容，原样，别改写成你的话>
```
```

- 每场之间加一行分隔说明（标题 + 包路径），方便用户对号。
- `PROMPT.md` 已经写好了「按顺序读三份材料 / 直接接着做 / 以时间靠后的为准 / 先讲理解再动手」，
  **别自己再润色**——润色会让不同场的提示词口径不一致。

### 4.1 派发提示词里必须有的两条默认口径（2026-11-02 用户定，「以后也是」）

用户原话：「交接时明确让 agent 重述我需要回答的问题，当时的提问我记不清。如果没有遗留问题就只让
agent 了解情况等我指示。（这两点也落为默认，对应两种交接情况怎么写派发提示）」

两条口径已写进 `tools/wb_takeover.py` 的 `_PROMPT_TMPL` / `_PROMPT_PEND`（两种交接形态各一份）：

| 情况 | 模板 | 派发提示里的措辞 |
|---|---|---|
| **有遗留问题** | 两份模板的第 1/2 条 | 「先重述**我要回答的问题**：逐条写『要我定什么 / 为什么非我不可 / 可选项或你的建议』。我是限流换号过来的，记不清当时被问了什么 —— 别只说『球在你那儿』，把问题本身摊开」 |
| **无遗留问题** | 两份模板的第 2/3 条 | 「只做情况汇报，3-5 行讲清现状，然后停下等我指示。⛔ 不要自己另找活干，也不要『顺手』加码」 |

为什么：① 用户换号后**记不清上一轮问了什么**，只给一句「在等你回话」等于把复述责任抛回给他；
② 没有遗留问题时，agent 容易自作多情找活干（项目红线：诊断类问答里不要顺手改代码），所以明确「停下等指示」。
⇒ **改模板时两条都要留**，两种收尾形态（被打断 / 等回话）各有一份，别只改一边。

- 提示词里的路径是**绝对路径**，用户在新会话里贴上去就能用；跨机或换盘才需要改。
- 新会话可能开在**不同工作目录**，但材料路径是绝对的 ⇒ 不受影响。提醒一句「先 cd 到 `原会话的工作目录`
  再动手」如果 `PROMPT.md` 里写了 cwd。

## 5. 坑（都踩过，别自己发挥）

1. **手机号反查不了 uuid**。`~/.workbuddy/*.json` 里没有 account/phone；`workbuddy.db` 只有 uuid。
   ⇒ 只用「最近活动的号」推断当前号，并**明说是推断**；解析不出就继续跑，别卡住问用户。
2. **收尾形态只能从 jsonl 尾条判断，不能看 `sessions.status`**。实测 19 场非正常收尾里只有 4 场
   `status='error'`，其余散在 `archived` / 已删除。`status` 是 UI 状态。
   ⚠ 但反过来，`status='archived'` 是**唯一**该信的字段 —— 它表示用户已明确收摊（285/326 场都是）。
   所以两个问题分开问：**怎么断的看尾条，还归不归你管看 status**。混用两头都会错。
3. **429 横幅必须从头锚定**。真实横幅是整条 assistant 消息的全部内容。曾用「子串包含」判定，
   把**上一场 agent 正文里引用过那句话**的会话误判成限流（本机 `44f8ef91` 就这么中招过）。
   脚本已 `re.match` 锚定，别改成 `in`。
4. **`chat_full.md` 里没有工具回显**。`dump`/export 只抽 `type=message`；`function_call` /
   `function_call_result`（一个会话实测 380 条）是独立事件。所以断点前的动作在 `HANDOFF.md`
   的「工具调用流水」和 `source.jsonl` 里。⚠ 也**别据此推断「当时的 agent 没看过这些输出」**。
5. **别把 scan 输出管道给 `head`**：虽然编号表已改成先落盘再打印，但 `| head` 会 SIGPIPE 掉
   后续逻辑（第一次实现就因此丢过 `last_scan.json`）。要截断用 `2>&1 | head` 之外的方式，
   或直接看全文。
6. **`[n]` 编号会随扫描条件变**：`--hours` / `--only` 一变，序号就重排。写结论时连
   `会话 id + 时间` 一起写，别只写「第 3 场」。
7. **同名的两场是同一件事的两次尝试**（如 `分析蔡风最新消息并推进项目进展` 一场在 playground、
   一场在项目目录）。挑「有实际改动 / `末工具` 更靠后」的那场，别两场都导。
8. **目录可能不是本项目**：`cwd` 可能是 `<user_home>/WorkBuddy/<时间戳>/`（playground）或别的盘。
   导包时照原样记录，别假设都在 `Parcae`。
9. **别顺手替用户改会话状态**。本 skill 只读库；不调 `wip_create`、不动 `sessions`、不删旧包。
10. **`status=completed` 不等于活干完了**。它只说明「agent 说完了」。实测 9 场 `completed` 里
    5 场末句在等你回话（§2 第二段就是为这个存在的）。判据是**末句措辞**，不是 status。
    ⇒ 所以第三段不能因为「已完成」就当没事，扫一眼标题再说。
11. **「等回话」判定的两条硬约束**（都踩过，别放宽）：
    - 问句型（要不要/需要我/是否要/要我）**必须同一句里以问号收尾**。否则
      「…（街拍路人是否要更严…）。B0047 起可直接抢」这种引用会被误判成在问你。
    - 命中多个时取**位置最靠后**那个。「## 两件需要你确认的 … 要不要你重启后端？」取第一个
      会截成小标题，真正的球在最后一句。
    - 代码块必须先剥（` ``` ` 里的 `if 你要不要` 会把整场判歪）。
12. **别把「接手会话」当成新的待接手场次**。用户派出去干活后，那个新会话的标题往往就叫
    「接手中断的 XXX」「继续 XXX」，而且比被接手的那场更新——它会顶到清单最前面，
    看起来像一场新活。判据：**清单里若有一场的标题正对应场上另一场的活，且时间更晚、消息更少，
    那它是接手会话**。这类要连同源会话一起说清「这场已被接手」，别两场都列成候选。
    ⚠ 顺手也会看到 `working` 的会话（用户正在里头敲），`--skip-current` 只挡当前号的，
    不是当前号在跑的仍会出现——列的时候标一句「正在跑」。

## 6. 与相邻 skill 的分工

| 场景 | 用哪个 |
|---|---|
| 换号后「刚才那几场断哪了、接着做」 | **本 skill**（`wb_takeover`） |
| 「这话我是不是说过 / 当时谁定的 / 找回原话」 | `wb-history-recall`（`tools/wb_history`） |
