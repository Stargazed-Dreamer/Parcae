## DOM 结构与提取规则

### 字段提取表

| 字段 | 选择器 | 注意事项 |
|------|--------|---------|
| 终端卡片 | `.term-card` | 所有终端字段都应先限定到唯一卡片 |
| 终端 ID/主要标签 | `.term-card-label` | 与 `.terminal-label` 可能显示相同文本 |
| 终端标签 | `.terminal-label` | 不可在全页面直接按可见文本假定唯一 |

### 页面布局变体

- 终端列表由前端动态渲染；卡片数量随会话创建、结束和删除变化。
- 同一终端名称可能在卡片内多个元素重复显示，文本定位器必须先限定卡片容器。

### 选择器优先级与回退

```javascript
const card = page.locator('.term-card').filter({ hasText: terminalLabel }).first();
const label = card.locator('.term-card-label');
```

长期建议在页面中增加 `data-terminal-id` 和唯一 `data-testid`；在此之前不要直接使用全局 `getByText(terminalLabel)`。

## URL 规则与重定向

- **后端 API**：`http://127.0.0.1:8766/health`、`/docs` 等。Web 监控面板已移除。
- **测试夹具**：其他 localhost 端口可能是临时测试页，不应套用本文件的 DOM 选择器。
- **主机别名**：`localhost` 与 `127.0.0.1` 都可能出现，browser lesson 匹配时视为同一本地站点入口。

## 已知坑（与正常行为区分）

| 问题 | 错误做法 | 正确做法 | 发现日期 |
|------|---------|---------|---------|
| 终端标签文本在同一卡片内重复出现，定位器产生多匹配 | 全局使用 `.terminal-label`、`.term-card-label` 或仅按文本点击 | 先用 `.term-card` + 标签文本锁定唯一卡片，再在卡片内部查字段；后续补 `data-terminal-id` | 2026-07-20 |
| 动态列表刷新后旧元素引用可能失效 | 长时间复用刷新前 locator/element handle | 每次操作前重新按终端 ID/卡片文本定位，并等待卡片状态稳定 | 2026-07-20 |
| 事务面板里「任务」「关闭」等文本会命中多个元素（tab / 抽屉 / 标题） | 只用 role+name 或纯文本点击 | 用稳定选择器：`.tab[data-tab="tasks"]`、`#drawer-close`、`.cand-card:nth-of-type(n)` | 2026-10-27 |
| `workspace/*` 是后端静态挂载，HTML 立即生效但新 API 要重启后端 | 改了后端路由立刻在浏览器断言成功 | 先看响应码：新路由未加载时是 405/404；静态文件与 API 生效时机不同 | 2026-10-27 |

## 遗留问题

- 监控面板尚未提供稳定的 Agent 选择器契约：唯一 `data-testid`、`data-terminal-id`、明确 role/name。
- 本轮只验证终端卡片相关结构，其他面板应在实际遇到非显然行为后继续补充。
